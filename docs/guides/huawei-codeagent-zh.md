# 华为 CodeAgent 接入说明

本分支为 Claude Code 和 Claude Desktop 增加 Huawei CodeAgent 2.0 / 3.0 预设、授权中心和本地代理认证。仅用于你有权使用的企业账号与网络环境。

## 使用条件

- 可以访问企业内部的 IDEA 登录服务和 CodeAgent 模型网关。
- 已有可用的企业账号。认证信息由 CC Switch 保存在本机，实际请求的 Token 由本地代理注入，不需要在供应商卡片里填写静态 API Key。
- CC Switch 需要保持运行，Claude Code 需要启用本地路由；Claude Desktop 使用模型映射模式。
- CodeAgent 3.0 的 Claude Code 预设还使用 `127.0.0.1:8888` 连通性代理，该端口不能被其他程序占用。Desktop 不启动这个 CLI 专用代理。

## 添加与切换

1. 在设置的授权中心找到华为 CodeAgent，使用自己的企业账号登录。也可以在供应商表单中的认证区添加账号。
2. 在 Claude Code 或 Claude Desktop 的添加供应商页面选择 Huawei CodeAgent 2.0 / 3.0。
3. 在账号选择框中选择这张卡片绑定的账号，或选择“使用默认账号”。每张卡片可以绑定不同账号。
4. 设置实际可用的模型。模型发现先验证并刷新所选账号，再尝试本机的 `nga models`；命令不可用或没有返回模型时使用内置候选列表。因此列表不代表所选账号一定拥有这些模型的权限。
5. 保存供应商。Claude Code 开启本地路由并将路由目标设为该供应商；Desktop 保持模型映射模式，按应用提示重启 Desktop 以加载配置。

更换绑定账号后，表单会清空此前拉取的模型列表；请求和模型查询的认证检查使用新绑定。显式绑定的账号被移除时，请重新选择账号，不会在后台悄悄使用另一个默认账号。旧版已保存的卡片建议打开编辑并保存一次，以补齐扩展元数据。

## 协议和生命周期

- Huawei 类型及旧别名 `huawei_w3` / `huawei_idea` 的实际出站协议统一为 Chat Completions。即使旧卡片记录的是 `anthropic`，请求和响应也使用同一协议判定，避免把 Chat 响应直接交给 Claude 客户端。
- Desktop 的华为配置允许不填写静态 API Key，但仍要求 Base URL；普通供应商不会因此免除凭据校验。
- 3.0 CLI 连通性代理由公共状态提交入口协调，覆盖供应商切换、路由变化和启动恢复。无效的切换不会先停掉原代理；启动或停止失败会向调用方报错，而不是仅写日志后报告成功。
- Desktop 的切换不会停止 CLI 连通性代理；退出 CC Switch 时清理该代理。连通性请求转交当前主代理端口，不再固定为默认端口。

## TLS 注意事项

现有华为预设默认设置 `skipTlsVerify: true`；3.0 CLI 预设还包含 `NODE_TLS_REJECT_UNAUTHORIZED=0`。这些设置会关闭对应连接的证书校验，不能当作一般网络问题的通用解决方案。只应在组织批准的环境中使用；具备可信证书链时应恢复证书校验。普通供应商不继承华为扩展的 TLS 默认值。

## Windows 构建

安装项目依赖后运行 `src-tauri\build.bat`。脚本会定位自身目录、初始化 MSVC、使用 Corepack 调用项目锁定版本的 pnpm 构建前端，再构建 Rust release 可执行文件；前端构建失败会中止，不会继续嵌入旧页面。

输出位置为 `src-tauri/target/release/cc-switch.exe`。这是独立可执行文件，不包含安装包和更新签名。脚本保留了企业内部 Rust 镜像设置，缺少工具链时需要能够访问该镜像。

## 验证边界

自动化测试使用人工账号数据、临时配置目录和本机临时端口，不读取实际登录凭据，也不访问企业模型服务。企业账号的真实登录、模型权限、实际流式调用以及 macOS / Linux 原生构建，仍应在对应的授权网络与平台中验收；本机 Windows 测试不能替代这些检查。
